Five routes implement four capabilities: step start and completion are separate accepted commands. No automatic Ready/start, signature creation, resume, verification, status setter or administration endpoint. Prerequisites and approval are supplied by the existing UI workflow. All service outcomes map consistently: Success 200 (initiation 201), InvalidInput 400, BusinessRuleRejected 422, Unauthenticated 401, Forbidden 403, NotFound 404, TechnicalFailure 503. Errors use ProblemDetails. Cookie-authenticated mutations require the native antiforgery cookie plus RequestVerificationToken header; clients obtain a token from the existing authentication Page. No additional token endpoint is needed.
