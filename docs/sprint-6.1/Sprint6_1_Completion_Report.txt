4. Actual REST contract and security
GET /api/production-orders/{orderNumber}, ManufacturingController.GetOrder, delegates to existing ProductionOrderService.GetAsync. Default MVC System.Text.Json behavior produces camelCase fields; enums are numeric, with no string-enum converter configured.
ProductionOrderView fields: orderNumber (string), productCode (string), productName (string), recipeId (string), quantity (decimal JSON number), status (integer enum). Status values: 0 Planned, 1 Released, 2 InProcess, 3 Completed, 4 Cancelled. No equipment or MES-connection field exists in this DTO.
API: cookie authentication; current active trusted actor required. Existing service read policy permits Production Operator, Production Supervisor or Quality Engineer; Administrator alone is forbidden. Anonymous API calls return JSON 401 without redirect. Controlled outcomes map to 400 invalid input, 401 unauthenticated, 403 forbidden, 404 missing, 422 business rejection and 503 technical failure; unhandled API faults are generic 500 ProblemDetails. Order text must be nonblank and at most 40 characters; the service does not impose a PO-number regex or trim the value. GET does not mutate records.
The new page inherits authenticated/no-store ManufacturingPageModel, resolves the actor through the existing IActorContext, and returns server-side 403 unless IsOperator is true. It does not use role claims from the cookie: the accepted identity implementation deliberately trusts current server configuration and active AppUser association instead.
Live --verify confirms demo.operator is active with Production Operator and Production Supervisor; demo.quality has Quality Engineer. Identity.log records only public identities/roles.

7. Route and behavior
Route: /shop-floor. Verified local URL: https://localhost:7099/shop-floor.
Standalone OEM Razor page with one plain text input, one Retrieve button and one inline context panel. Native form submit handles Enter as well as button clicks. No scanner interception/library, casing transformation or trimming. Input regains focus and selection after retrieval. Invalid/empty/control-character input is rejected clearly. Encoded values are sent unchanged to the API. Duplicate pending submissions are blocked; requests time out after 15 seconds. Old results are cleared before another retrieval. Feedback distinguishes invalid input, missing orders, expired sessions, forbidden access, unexpected responses and other failures. Values use textContent only.
The existing cookie login previously always redirected to /. The small Presentation change accepts only .NET-validated local return URLs, preserving / when absent/unsafe. Existing cookie, antiforgery, rate-limit, credential and API policies remain in place.
